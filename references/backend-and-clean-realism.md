## 五种交付模式

默认使用 `strict-final`：结果必须保持身份、冻结边界、未授权内容、构图与宽高比。输出可因图片后端限制等比例缩小，不要求与源图像素尺寸相同。完整要求由交付模式表达，不再把 `exact_identity_required` 作为可选场景标志。

只有满足局部蒙版和未编辑像素直通的后端才执行严格模式。后端不满足时自动降级为 `best-effort`，仍然调用可用图片编辑工具并生成结果，不再因为面部尺寸、复杂场景、文字或后端能力不足而拒绝处理。尽力结果必须标记“非严格尽力编辑”，不得声称像素冻结或严格身份保持。

只有完成工具注册表发现、并确认不存在兼容图片生成/编辑 callable 时，才使用 `invocation-handoff`。继续分析源图并输出已展开的完整 image edit 提示词；不得把错误函数名、错误参数或尚未调用已发现工具描述成能力缺失。

当前智能体自身的 imagegen Skill/原生生图能力存在真实工具调用记录，并且同一调用明确报告 built-in 生图不可用或失败时使用 `prompt-only`。继续分析源图并输出已展开的完整 image edit 提示词；不声称生成图片，也不只返回“环境不支持”。

图片工具已经运行，但结果在正常观看倍率下没有解决必需目标、与原图近乎相同，或触发身份、保护项、脏化、光影、宽高比/构图硬失败时使用 `prompt-handoff`。等比例缩小不是失败。告知本次图片结果未达到目标改善，并输出基于原图的完整提示词；失败图不得冒充成片。

## 原生 Imagegen 默认路由

固定按以下顺序执行：

1. 读取当前智能体自己的原生图片生成 Skill；Codex 使用 `$imagegen`，其他智能体使用其等价说明；
2. 检查当前工具注册表并记录发现证据。Codex 从 `ALL_TOOLS` 查找真实 callable，优先选择准确名称 `image_gen__imagegen`；
3. 源图是本地文件时先查看源图；Codex 编辑调用使用 `tools.image_gen__imagegen({referenced_image_paths: [绝对路径], prompt})`；不得调用猜测的 `tools.image_gen`，不得使用猜测的 `input_image`；
4. 发现兼容工具后必须调用。错误成员访问或错误参数导致的 `TypeError` 只算调度错误，重新发现并按正确签名重试；
5. 原生图片工具返回后，再根据实际能力分级为 `strict-local` 或 `full-frame-generative`；
6. 只有发现完成且确认没有兼容工具时进入 `invocation-handoff`；正确工具有调用记录且明确返回 unavailable/failed 时才进入 `prompt-only`；有图片结果时继续分级与验收。

默认禁止 CLI/API fallback；用户明确要求该路径时，交回原生 imagegen Skill 按其自身规则决定，不由 XXG Skill绕过。

## 调用证据契约

| 状态 | 必需证据 | 禁止说法 | 交付模式 |
| --- | --- | --- | --- |
| 图片已生成 | 图片工具调用记录 + 返回图片、结果 ID、可访问文件或图片内容 | 只有文字说明却声称已生成 | `strict-final` 或 `best-effort`，再做验收 |
| 图片调用失败 | 图片工具调用记录 + 同一调用的明确错误载荷 | 没有调用记录却声称 imagegen 失败 | `prompt-only` |
| 未发现兼容工具 | `tool_discovery_completed: true` + 已记录候选名称 + `selected_image_tool_name: null` | 在发现前交接；忽略已发现的 `image_gen__imagegen` | `invocation-handoff` |
| 本地调度错误 | 调用了未发现的成员、错误函数名或错误参数；例如 `tools.image_gen`/`input_image` 导致 `TypeError` | 把调度错误说成图片后端失败或无工具 | 纠正调用并重试，不得交接 |
| 已生成但目标失败 | 图片结果存在 + 视觉或文件验收失败记录 | 把近乎原图或失败图当成成品 | `prompt-handoff` |

`<codex_delegation>`、创建/发送后台任务、任务完成文本、读取 `$imagegen/SKILL.md`、输出“开始调用”或查看源图都不是图片工具调用，也不是不可用证据。访问不存在的 `tools.image_gen` 同样不是原生工具调用。任何执行上下文都必须先完成注册表发现；若 `ALL_TOOLS` 已列出 `image_gen__imagegen`，就必须按其签名调用。`prompt-only` 的错误说明应引用正确工具的真实调用状态或错误摘要，不得凭空编造。

## 后端能力检查

原生 imagegen Skill 选定 built-in 路径后，再匹配 [backend-capabilities.json](backend-capabilities.json)。只有路由方式、整图引用、蒙版与像素直通等条件完全一致时才使用已登记档案；未知路径保守归类为 `full-frame-generative`。使用登记档案时运行 `scripts/evaluate_backend_gate.py` 并保留 JSON 输出。`strict-local` 必须是任务开始前已由环境提供的语义图片编辑能力；临时 Pillow/NumPy/OpenCV 脚本、命令行滤镜或普通图像处理管线一律不算图片后端。

生成前逐项回答：

| 能力 | 严格要求 |
| --- | --- |
| 任务开始前已由智能体原生 imagegen Skill 暴露的 built-in 能力 | 必须 |
| 语义图片编辑能力，而非传统像素滤镜 | 必须 |
| 皮肤/受光区域蒙版 | 必须 |
| 眼睑、虹膜、鼻翼、唇线、下颌、头发、服装和背景冻结蒙版 | 必须 |
| 未编辑像素原样直通 | 必须 |
| 固定原始画布 `W × H` | 仅用于证明严格像素直通；不是普通结果的交付尺寸要求 |
| 本地结果文件可用于宽高比检查；同尺寸时可做差分检查 | 必须 |

任何一项缺失即归类为 `full-frame-generative`。不要把提示词中的“冻结”“保持不变”当作工具能力，但能力缺失只触发降级和保守策略，不触发停止。

Pillow、NumPy、OpenCV、ImageMagick、FFmpeg 和 `sips` 只能用于只读量测或审计；禁止用于生成、补光、调色、加纹理、磨皮、锐化、裁切、扩边、缩放、合成或修复交付图片。

## 集中生成决策

按顺序执行。先调用原生 imagegen Skill，再对它选定的 built-in 路径分级：

| 后端与场景 | 决策 | 可声称的结果 |
| --- | --- | --- |
| `strict-local` + `strict-final`，全部必要能力和编辑计划已验证 | 允许局部编辑 | 通过全部验收后可交付严格成品 |
| `full-frame-generative` + `strict-final` | 自动降级并生成 | 标记为“非严格尽力编辑”，列出缺失能力 |
| `full-frame-generative`，面部 `<256 px` | 纹理关闭，光影按用户目标生成 | 不追求毛孔，但宽缓受光和环境一致性必须在正常观看下可辨改善 |
| `full-frame-generative`，复杂场景、文字/商品/精细物体、多人或主体触边 | 降低背景重绘与纹理，保留目标光影预算 | 逐项点名保护物；允许同一主光造成必要亮度和反射响应 |
| 原生 imagegen 选中未登记的 built-in 图片编辑路径 | 按整图后端降级并生成 | 标记后端未验证，不声称严格保持 |
| 工具发现完成且确认不存在兼容图片 callable | `invocation-handoff` | 说明未发现可调用图片工具并输出完整提示词；不得声称工具失败 |
| 有图片工具调用记录且明确返回 unavailable/failed | `prompt-only` | 输出已展开、无占位符、可复制的完整 image edit 提示词；附真实错误摘要，不声称已生成图片 |
| 图片结果未通过目标改善门、身份/保护门或宽高比/构图门 | `prompt-handoff` | 告知失败，直接输出基于原图的完整提示词；等比例缩小不得触发此分支 |

`256–511 px` 面部的整图尽力编辑不把皮肤微纹理作为硬目标。面部 `<256 px` 时关闭新增微纹理，禁止主动制造毛孔、绒毛、黑头或细纹；这些限制不得降低用户明确指定的场景级光影。整图提示必须分别列出结构不变量、允许的外观变化和一个 100% 完整画面可辨的最低改善目标。结果与原图近乎相同不能以“处理克制”判通过，也不能证明身份、发丝、背景或服装得到像素级保持。

选择 A6 时不按普通皮肤任务降强度：无论面部尺寸，整个人物内部都必须成为连续全黑的逆光剪影。把人物内部亮度、肤色、头发、衣物、饰品和五官可见性列入授权外观变化，把外轮廓、比例、姿态、构图与背景物体列入结构不变量；后端不能局部冻结时仍执行 `best-effort`，不得回退为只压暗面部。

## 干净真实感模型

把皮肤拆成三层，不混为“增加细节”：

### 低频：基础肤色

- 保持原图肤色基准和连续色调；实际亮度服从选定光源与曝光意图；
- 允许由光线造成的宽缓冷暖与明暗渐变；
- 禁止斑驳红黄块、脏灰阴影、局部漂白、肤色断层和脸颈分离；
- 有效受光区域应干净、自然、健康；剪影和深暗区域不要求恢复成明亮肤色。

选择 A6 时跳过低/中/高频肤质可见性验收；人物内部应为干净连续黑色，不能残留局部肤色、面光、眼神光、发丝或衣纹，也不能用颗粒制造黑色层次。

### 中频：曲率和受光

- 通过颧部、鼻部、下颌和颈肩的受光、遮挡和投影表现体积；
- 阴影边缘服从光源面积：柔光宽缓，硬光清楚；不得使用与光源不符的局部锐化；
- 禁止加深眼下、法令纹、鼻翼沟、嘴角或颈纹来“雕刻”立体感；
- 禁止局部 clarity/dehaze、高反差 dodge-and-burn 和 HDR 轮廓。

### 高频：皮肤表面

- 毛孔、绒毛、浅细纹和唇纹必须低对比、低密度、大小不一致；
- 毛孔表现为细微反射与明暗变化，不是黑点；
- 黑头、痣、雀斑、卡粉、浮粉、粉屑和干皮默认只保留源图已存在内容；
- 用户明确要求新增鼻翼黑头时，只在高分辨率近景中加入极少量低对比点状层次，并优先保证干净感；
- 不添加全局颗粒、色噪、锐化砂感或重复纹理。

## 光影立体感边界

真实立体感来自光源方向、面积、距离、环境反射和遮挡，不来自对五官周围随意加深。

- 每次先记录 `exposure_intent: source-matched | balanced | highlight-priority | shadow-priority | low-key | silhouette | high-key`，再决定 Fill、阴影深度和高光滚降；
- 使用大面积柔光时，保持阴影边缘宽、亮度过渡连续；
- 使用补光时，只在曝光意图要求暗部可读时抬升阴影，不新增第二套鼻影或眼神光；
- 逆光默认优先保留亮源、背景曝光和发丝轮廓；面部可深暗或成为局部剪影。只有用户明确要求补面时才加入低强度环境反射；
- `low-key` 与 `silhouette` 允许大面积暗部接近黑色；`highlight-priority` 允许亮源附近少量自然溢出。不能因“内容不够清楚”自动改成平衡曝光；
- A6 强制使用 `silhouette + fill none`：删除主光配方中所有人物正面/侧面照明，让背景或人物后方光源正常曝光，人物内部完整落为全黑；只允许不侵入人物内部的极窄同源轮廓溢光；
- 室内窗光必须同时解释人物、衣物、桌墙、金属/玻璃反射和房间深处衰减；做不到时回退到 `match-source`；
- 禁止用额外颗粒、局部锐化、脏灰阴影或无来源烧暗制造“摄影感”；物理合理的深暗和剪影不是失败。

## 画外窗光置信度

记录 `confidence` 与 `evidence`：

- `high`：可见窗户，或至少三类独立证据一致，例如眼神光、物体投影、金属反射和空间亮度衰减；允许明确 `relight`。
- `medium`：两类证据大体一致但窗户不可见；只允许低幅度方向性修正，不生成光束、光斑或新窗位。
- `low`：证据不足或冲突；使用 `match-source`，只修复无来源亮暗、不连续过渡和与原曝光意图不符的高光/暗部截断。

不得把推测写成确定事实。每个光影提示必须说明证据物体。

## 失败响应

- 原生 imagegen 选中的 built-in 后端能力不足：自动改用 `best-effort`，降低编辑强度并生成图片；说明缺少的严格能力。
- 工具注册表发现完成且确认不存在兼容图片 callable：改用 `invocation-handoff`，明确说明未发现可调用图片工具并直接输出完整 image edit 提示词。发现了正确工具但未调用、或调用了错误名称/参数时不能触发此分支。
- 有真实图片工具调用记录且调用明确不可用/失败：改用 `prompt-only`，引用错误摘要并直接输出完整 image edit 提示词。
- 目标改善失败或与原图近乎相同：改用 `prompt-handoff`，明确告知失败并直接输出完整提示词；不得以“克制”为理由判通过。
- 身份、保护区或宽高比/构图失败：改用 `prompt-handoff`；等比例缩小不触发失败，不得用本地脚本缩放或裁切修复。
- 皮肤变脏、变粗、斑驳或光影出现假立体：改用 `prompt-handoff`，把清洁肤色、宽缓受光与禁用局部加深写成明确修正要求。
- A6 结果仍有面光、肤色、眼神光、发丝高光、衣物内部细节或灰色填充：改用 `prompt-handoff`，删去普通 S 句与人物正面受光，明确要求整个人物内部连续全黑。
